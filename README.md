# 中转站收录
整理公开可访问的 AI API 中转服务信息，方便开发者按模型覆盖、价格和服务透明度进行比较。
> 本项目是信息索引，不提供中转服务，也不代表对任何服务商的背书。服务能力、价格、可用性和条款可能随时变化；使用前请自行核实，并避免提交敏感数据。

## 公开模型检测（OmwAI-Detector）

导航“模型检测”进入 `/detector`，无需注册或登录。访客自带公网 HTTPS API 前缀、模型 ID 和专用低额度 Key，可选 Responses / Chat Completions 协议检测，或服务端公布的固定型号、固定上游模型 ID 的行为指纹对照。协议检测最多 2 次请求；行为检测按实时能力接口显示档位、精确请求数和单次输出上限，必须勾选授权及费用确认。协议通过不证明型号真实，行为对照不是“真品概率”，无基准型号不提供身份结论。

部署步骤：

1. 独立部署 OmwAI-Detector 的 API、Worker、MySQL 和 Redis；启用行为检测还需配置其 Python 评分运行环境，按 Detector 自身说明部署。Lab 不复制检测引擎，不自动启动第二个项目。
2. 在 Lab 服务端环境配置 `DETECTOR_URL`（例如 `http://127.0.0.1:8787`）、`DETECTOR_ADMIN_TOKEN`（Detector 的 `ADMIN_TOKEN`）和独立随机的 `DETECTOR_ACCESS_SECRET`（至少 32 字符），见 [.env.example](.env.example)。远程 Detector 必须 HTTPS；不设置任何 `VITE_` 令牌。不配置时公开接口返回 503，页面明确提示服务未配置。
3. 构建并重启 Lab；将 Detector API 保持在私网/回环地址，不直接公开其运营 API。HTTPS 部署正确配置 `PUBLIC_ORIGIN`；仅当反向代理覆盖 `X-Forwarded-For` 且禁止绕过代理访问时启用 `TRUST_PROXY=true`。

Lab 提供 `/api/detector/capabilities`、`POST /api/detector/tasks`、`POST /api/detector/fingerprint-tasks` 和 `GET/DELETE /api/detector/tasks/:id`。创建需 `consent: true`；查询和取消需创建返回的独立 `X-Detector-Access` 签名凭证（绑定任务，24 小时有效），不使用用户登录身份。凭证仅保存在当前标签页的 sessionStorage；刷新可恢复报告，关闭标签页可能失去查询权，不会自动取消。浏览器不存 API Key，提交成功立即清空；Detector 加密暂存并按其任务生命周期清除。代理不向前台返回原始任务输入或内部运营令牌，不记录请求正文；部署方也必须禁用代理层的正文/敏感头日志。

公开入口有独立进程内保护：每 IP 每小时最多 5 次提交、全局每小时最多 100 次、全局至少间隔 5.5 秒；查询等每 IP 每分钟最多 120 次。不重试创建任务、不自动降级协议，失败或取消中的在途请求可能产生费用。**当前应以单 Lab API 进程部署**：限流是进程内计数，重启清零，不是跨实例配额；扩容前需在网关部署共享限流，公开部署还应配置抗滥用与连接限流。匿名限流不能阻止分布式恶意流量，不能将 Detector 的运营预览直接暴露公网。Detector 需独立运行，未配置真实服务或未启用评分器时，不应宣称完整检测已上线。

定向验证：`npx tsc -p tsconfig.server.json` 后运行 `node --test server/detector.test.mjs`。测试使用本地模拟 Detector，不发送真实计费请求。

## 后台运营概览

趋势区的“查看每日明细（含 UV）”在独立模态弹窗中展示日期、PV、UV 和官网跳转，不展开原页面；支持关闭按钮、Esc 或点击遮罩关闭，关闭后焦点返回入口。

管理后台的数据概览支持今日、昨日、近 7 天、近 30 天筛选，按北京时间展示前台 PV、匿名访客 UV、官网跳转次数与人数、导流转化率、新增本地账号、新增收录申请，并展示当前公开站点、三类审核待办、48 小时积压、每日趋势、热门页面、热门站点、数据同步健康及最近操作。

前台通过同源 `/api/analytics/events` 上报页面浏览、访问官网意图和确认跳转，管理端 `/api/admin/dashboard?range=7d` 聚合查询。匿名访客标识保存在浏览器本地，会话在连续 30 分钟无活动后更新；不采集 URL 查询参数、表单正文或密钥，不统计后台和登录页。官网跳转只表示用户点击“确认并继续”，不代表外站成功加载、注册或成交。UV 仅按有效页面浏览去重；全站导流率为所选周期内先浏览、后跳转的匹配去重访客数除以前台 UV，站点导流率要求浏览与跳转对应同一站点，分母为零时显示“—”。本地账号不包含尚未统一持久化的 GitHub / Google 登录身份。

部署后重启后端完成统计表初始化；流量仅从采集上线后积累，不回填历史访问。采集起点为统计表首次初始化时间，重启不会重置。原始事件保留约 90 天，有效访问触发限频、分批清理，低流量下删除可能延迟；不保存完整 IP。管理员登录状态的访问不采集。统计起点之前的数据不可追溯；公开站点、审核积压与同步健康为当前状态，不随时间筛选变化。客户端匿名统计是运营参考，不作为结算依据；清除浏览器存储、跨设备及自动化访问会影响准确性。

## 我的站点与修改审核

管理后台统一从「站点审核」进入，在页面内通过「收录申请 / 修改申请」标签切换。数据概览的收录、修改待办分别直达对应标签；修改申请仍保留版本对比，通过后才更新公开资料，驳回不影响当前收录版本。

“我的站点”使用紧凑表格，每行一个站点，支持名称 / 网址搜索和每页 10 条分页。“查看”打开详情模态框，在弹窗内查看资料、公开展示状态及独立报价管理。

已通过审核的站点，名称、网址、成立时间、介绍、模型覆盖、价格说明、计费方式、发票、Logo 和补充说明的修改均作为独立申请重新审核。待审、驳回或撤回时，原有收录资料与公开展示保持不变；管理员通过后才会原子更新为新版本。同站点只允许一份待审修改，可撤回后重新提交。公开展示开关不需要重审，分组与报价仍使用独立审核流程。

二次编辑有未保存的修改时，关闭弹窗、按 Esc、点击弹窗外侧、返回详情或站内跳转（包括浏览器后退）会提示“放弃修改？”，可选择继续编辑或放弃修改。刷新或关闭标签页使用浏览器原生离开确认（文案由浏览器决定）；未修改、已恢复原值或提交成功后不提示，提交过程中禁止从弹窗退出。

管理员在“管理后台 → 修改审核”查看前后资料对比，并通过或驳回申请。后端启动时自动创建修改记录表及唯一待审约束；部署新版本后需重启后端完成迁移。

## 计费方式

提交收录时必须选择计费类型：按量计费、按次计费、包月订阅、混合计费或其他，可填写最多 1000 字的公开补充说明。已审核站点可在“站点管理 → 我的站点”补填、修改计费信息。目录计费方式列展示实际类型及说明，而非参考倍率；历史未填写记录显示“未填写”，不推断计费类型。后端启动时自动添加 `submissions.billing_type` 和 `submissions.billing_details` 可空字段。

## 发票信息

提交收录时必须明确选择是否支持发票。审核通过的站点可在“站点管理 → 我的站点”补填或更新发票信息，目录显示绿色“✓ 支持”或红色“× 不支持”。历史记录没有填写时仍显示“未提供”，不会推断为不支持。后端启动时会自动添加可为空的 `submissions.invoice_supported` 字段，无需重建数据库。

## 模型列表检索

定价与排行榜每页显示 30 条，筛选针对完整已加载模型集，不只筛选当前页。定价搜索框即时更新输入，暂停输入 250ms 后将关键词写入 URL，避免逐字路由导航造成卡顿和丢字；厂商筛选、详情返回链接保留检索条件，筛选变化时回到第一页。

## 外观模式

网站默认保持原有浅色模式。点击顶部导航栏的月亮 / 太阳按钮，可以切换深色 / 浅色模式，移动端同样可用。选择会保存在当前浏览器中，刷新或重新打开后继续使用；浏览器禁用本地存储时，仍可切换，但不会记住选择。全站页面及登录人机验证组件随主题切换。

## 生产部署

要求 Node.js **22.12+**（推荐当前 LTS）与 npm。开发使用 `npm run dev`；正式部署使用独立 Node HTTP 服务，不使用 `vite preview`。开发和生产复用 `server/backend.ts` 的 API，构建时由 TypeScript 编译后端到 `dist-server`，前端输出到 `dist`，运行时无需 Vite 或 TypeScript。

```powershell
npm ci
# 首次部署：复制模板并在本机编辑配置，切勿提交凭据。
Copy-Item .env.example .env
npm run build
# 可选：构建完成后移除构建依赖；也可在部署机器 npm ci --omit=dev。
npm prune --omit=dev
npm start
```

已有 `.env` 时不要覆盖它。部署机器需同时具备 `dist`、`dist-server`、`package.json`、`package-lock.json`，并安装生产依赖 `npm ci --omit=dev`；重新构建前需恢复完整依赖 `npm ci`。MySQL、Redis、SMTP 都是运行时 dependencies，不依赖开发安装。现有 React 传递依赖可能产生 peer dependency 警告；构建可能提示前端大 chunk，不影响启动。

### 监听、HTTPS 与代理

- `npm start` 自动加载根目录 `.env`（不存在也可启动），系统环境变量优先；生产入口不读取 Vite 的 `.env.production`。默认 `HOST=127.0.0.1`、`PORT=3000`，Windows 可用 `$env:PORT='3000'; npm start` 覆盖。
- 在 Nginx、Caddy 或云负载均衡器终止 HTTPS，将**全部路径**原样转发到 Node；保留 Host，并覆盖客户端提供的 `X-Forwarded-For`。不要把 `/api` 转给前端静态托管。限制请求体大小并设置合理超时。应用端口仅对可信代理开放，才可启用 `TRUST_PROXY=true`。
- 设置 `PUBLIC_ORIGIN=https://你的域名`（不带结尾 `/`），Google OAuth 回调使用这个固定外部地址，不从不可信转发头推导。GitHub/Google 控制台均需登记实际域名的 `/api/auth/github/callback`、`/api/auth/google/callback`。
- HTTPS 上务必设置 `COOKIE_SECURE=true`；本地 HTTP 测试保留 `false`。SMTP、Turnstile、验证码密钥、站点加密密钥的配置见下文及 `.env.example`；不同密钥独立生成并保管。
- 静态服务仅暴露 `dist` 内非隐藏文件，阻止路径穿越及越界软链接；哈希 assets 长缓存，HTML 不长期缓存。SPA 回退仅适用于 GET/HEAD 页面请求，缺失资源及 API 不回退 HTML。

### 可用性、限制与验证

`GET /api/health` 是不访问数据库/Redis 的**进程存活检查**，不是依赖就绪检查；静态页面及无 Cookie 的 `/api/auth/me` 无需数据库；携带会话时需要 Redis，本地账号还需 MySQL 校验。MySQL 在首次需要它的 API 请求时初始化表结构；缺配置或连接失败返回脱敏 503，随后请求可以重试。正式部署前需配置可访问的 MySQL 8.x（初始化需要建表/变更表权限）、Redis，以及邮件/人机验证与 OAuth；价格和排行数据需按已有命令同步。健康接口成功不代表这些功能已就绪。

**登录会话持久化**：登录会话已迁到共享 Redis，应用重启、重新运行 `npm run dev` 不会清空有效登录；各实例必须使用相同 Redis 数据库及键前缀。OAuth state 和尚未完成的 MFA 登录挑战仍在进程内存，进行中的认证流程重启后需重试，多实例完整登录流程仍需粘性路由，不能直接宣称支持无粘性多实例。建议使用系统服务/进程管理器托管 Node 实例。收到 SIGINT/SIGTERM 时停止接收连接，等待进行中请求并关闭 MySQL、Redis、邮件资源；10 秒后关闭残余 HTTP 连接，15 秒整体退出上限。Windows 本地使用 Ctrl+C 停止。

```powershell
npm run test:server
# 构建后启动并在另一个终端检查：
npm start
curl.exe http://127.0.0.1:3000/api/health
curl.exe -I http://127.0.0.1:3000/
```

## 账号与邮件配置

本地账号支持邮箱验证码注册、用户名或邮箱登录，以及邮箱验证码重置密码。验证码 10 分钟有效，同一验证码最多尝试 5 次，发送及认证接口包含基础频率限制。SMTP 凭据只从环境变量读取；复制 `.env.example` 为 `.env` 后配置 `SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURE`、`SMTP_USER`、`SMTP_PASSWORD`、`SMTP_FROM`，并为 `EMAIL_VERIFICATION_SECRET` 设置独立随机密钥。

### Redis（必需）

登录会话、邮箱验证码、发送冷却和认证接口限流使用共享 Redis，不再读写 MySQL 的 `email_verification_codes` 表，也不回退到进程内存。配置 `.env` 的 `REDIS_URL`（标准 `redis://`，生产托管实例优先使用 TLS `rediss://`）及可选的 `REDIS_KEY_PREFIX`（默认 `omwai:auth:`）。连接凭据中的特殊字符需 URL 编码；不同环境应使用不同前缀，同一环境的应用实例需使用相同前缀及 `EMAIL_VERIFICATION_SECRET`。

- 验证码以 HMAC-SHA256 哈希保存，10 分钟 TTL 自动删除；注册与重置密码相互隔离。
- 同一邮箱同一用途发送冷却 60 秒；新验证码覆盖旧验证码。发送失败时仅撤销本次记录。
- Lua 脚本原子校验与消费，最多尝试 5 次，成功后立即删除，防止并发重放。
- 登录、注册、发送验证码、重置密码按 IP 共用每 15 分钟 20 次的固定窗口限制，跨进程共享。
- Redis 缺失或不可用时上述接口返回 503。校验成功后若 MySQL 写入失败，验证码不会恢复，需冷却结束后重新获取。
- 切换后原 MySQL 验证码失效，用户需重新获取；保留旧表，不自动删除历史数据。

生产 Redis 应启用认证、TLS、私网访问、高可用及持久化（如 AOF，按业务可接受的数据丢失窗口配置刷盘），推荐使用专用实例和 `noeviction` 策略，避免验证码或限流键被提前驱逐。Redis 账号需允许 `EVAL` 及脚本使用的 `GET`、`SET`、`EXISTS`、`DEL`、`HGET`、`HSET`、`HINCRBY`、`PEXPIRE`、`INCR` 命令，并限制到应用键前缀。客户端使用有界连接/命令超时，断线后自动重连。

默认仅使用直连 IP；仅在可信反向代理覆盖 `X-Forwarded-For` 且应用端口不对公网开放时配置 `TRUST_PROXY=true`。登录会话已共享；OAuth state 和待完成的 MFA 挑战仍在进程内存，完整认证流程多实例部署仍需粘性路由。

先执行 `npx tsc -p tsconfig.server.json`，再执行 `node --experimental-strip-types --test server/auth-redis.test.ts` 运行离线测试；设置专用测试实例的 `REDIS_TEST_URL` 可同时执行真实 Redis 集成测试（随机隔离前缀，不使用生产配置）。

登录、注册、发送验证码和重置密码均使用 Cloudflare Turnstile，并在服务端验证一次性 Token 及对应 action；前端验证结果本身不作为可信依据。验证过期、超时或失败后不会在闲置页面自动循环验证，而是提示用户点击“重新验证”；Token 过期时立即清空，提交前仍须取得有效 Token。发送邮箱验证码会消耗 Token，之后提交注册或重置密码时需要再次验证。请在 Cloudflare Turnstile 控制台添加生产域名和本地开发域名，然后配置 `TURNSTILE_SITE_KEY` 与 `TURNSTILE_SECRET_KEY`。HTTPS 生产环境还应设置 `COOKIE_SECURE=true`。

## 会话与请求来源防护

会话 Cookie 使用 `HttpOnly; SameSite=Lax; Path=/`，不设置共享 Domain。`COOKIE_SECURE=true`、`NODE_ENV=production` 或 `PUBLIC_ORIGIN` 为 HTTPS 时自动启用 `Secure`；本地 HTTP 开发不要设置这些生产选项。退出时以相同 Cookie 属性清除会话。普通用户会话最长 7 天、空闲 24 小时失效；管理员最长 12 小时、空闲 30 分钟失效。登录及 MFA 验证成功会轮换会话 ID；密码重置和角色变更撤销该账号已有会话。每次使用本地账号会话均重新检查账号及角色，数据库不可用时拒绝认证请求。退出登录不依赖数据库可用性，但必须成功从 Redis 撤销会话后才清除 Cookie；故障时返回 503，前端保留登录状态并提示重试。

所有 `/api/` 非 GET/HEAD/OPTIONS 请求都校验 `Origin`，缺失时使用 `Referer` 的来源；来源不匹配、没有来源或 `Sec-Fetch-Site: cross-site` 返回 403。浏览器同源请求无需额外 Token；脚本客户端必须明确发送本站 Origin（仍须有效认证，来源校验本身不是认证）。生产环境请设置固定的 `PUBLIC_ORIGIN=https://你的域名`，不要依赖不可信的转发 Host；反向代理必须保留浏览器 Origin/Referer。该实现不支持跨域写 API。认证及私有 API 返回 `Cache-Control: no-store`。

会话使用 32 字节安全随机 ID，Redis 仅保存 ID 的 SHA-256 哈希键与会话资料；会话读取、空闲续期和账号撤销校验由 Lua 原子执行，活动不会延长绝对有效期，Cookie 有效期与绝对期限一致。账号级撤销使用持久化版本号，使所有实例中的旧会话立即失效；版本号不要手动删除。首次升级后旧的内存会话需重新登录一次，此后重启应用不再掉登录。Redis 不可用时返回 503，不清 Cookie、不回退内存；前端提示并每 5 秒重试恢复登录。`npm run test:server` 包含离线会话测试，设置专用 `REDIS_TEST_URL` 后同时验证真实 Redis 的重启、跨实例、退出、撤销及过期行为。

## 模型价格与发布日期人工修正

后台菜单「模型价格管理」位于「数据概览」下方，提供新增真实 API 模型、数据库记录搜索、25 条分页、输入 / 输出 / 缓存读取价格、发布日期和核验来源编辑。列表按生效发布日期倒序排列，未知日期置后，同日期按提供商、名称与精确身份稳定排序；刷新统一使用列表工具栏的「刷新列表」。价格单位为 USD，默认每百万 Tokens；图片 / 视频沿用该记录计费单位。空价格 / 日期表示未知，0 表示免费；日期须为真实 `YYYY-MM-DD`，来源必须填写名称及无凭据的 HTTP(S) URL。来源链接仅作引用，不会抓取，不推测缺失价格或发布日期。

- `GET /api/admin/model-prices?q=...&page=1&pageSize=25`：搜索原始来源、提供商、模型 ID 或名称（pageSize 最大 100）。`PUT` 同路径保存整组覆盖，`DELETE` 同路径清除覆盖；请求体使用 `sourceId`、`providerId`、`modelId` 精确身份。PUT 另需 `inputPrice`、`outputPrice`、`cacheReadPrice`（数字或 null）、`releaseDate`（日期或 null）、`sourceName`、`sourceUrl`。
- `POST /api/admin/model-prices` 新增 `source_id=manual` 记录：`providerId`、`modelId` 必须为真实提供商及 API 调用 ID，`name`、`providerName`、`billingUnit`、`modality`（text/image/video/audio）必填；价格、发布日期与核验来源字段同 PUT，可选布尔 `reasoning`、`openWeights`。人工来源下同提供商 / 模型 ID 重复返回 409（包含并发新增），不得使用排行榜 slug 冒充调用 ID。新增与审计同事务持久化。
- 初始化自动创建独立的 `model_price_overrides` 表，使用二进制精确身份键，不修改底层原始值。BaseLLM 价格同步不清除人工来源或覆盖；模型临时从源中消失时保留覆盖，精确身份重新出现后再次应用。Artificial Analysis 同步只更新排行榜及同步日志，绝不新增、更新或删除定价记录。
- 保存覆盖整组价格、发布日期和核验来源；清空字段表示显式未知，不是逐字段回退。「恢复原始数据」删除整组覆盖；同步来源恢复最新同步资料，manual 来源恢复首次新增底值，不删除模型。编辑弹窗默认仅展示身份、价格单位和表单，原始价格、日期及来源收在「查看原始数据 / 恢复预览」折叠区；恢复需二次确认，确认期间禁用保存，防止误操作。
- 公开模型价格目录从数据库读取覆盖后的结果，但原始能力排行榜仍展示其独立同步指标；人工编辑不修改排行榜指标。多个来源合并的同名模型优先选择人工 manual 记录，其余保持既有合并优先级，修正的是所选精确记录，而非全局同名模型。
- API 位于现有管理员认证、MFA（已启用者写操作须近 5 分钟验证）、同源写防护及私有响应 no-store 保护之内。新增 / 修改 / 恢复与含身份、前后覆盖值的审计记录在同一事务内提交。
- 上线需重启后端执行幂等建表（数据库账户须有建表权限）；本功能没有自动调度外部同步，独立价格同步仍由已有 BaseLLM 同步脚本触发；后台排行榜同步不维护定价。

离线验证：`node --experimental-strip-types --test server/admin-model-prices.test.ts`。这些测试使用模拟数据库，不修改生产数据；实际 MySQL 建表 / SQL 执行、管理员登录后保存 / 恢复还需在部署测试库验收。

## 管理员 MFA（渐进启用）

本地管理员可在头像菜单的「安全设置」（`/security`）自愿绑定 TOTP；未绑定时仍保留现有管理权限。先配置独立的 `MFA_ENCRYPTION_KEY`（32 字节随机值的 base64，生成方式见 `.env.example`），重启后端。不要复用站点凭据密钥，不要提交到版本库，并与数据库一起安全备份；密钥遗失或更换会导致现有验证器密钥无法解密。

绑定时先确认当前密码，将页面显示的密钥手动添加到验证器（TOTP / SHA1 / 6 位 / 30 秒），10 分钟内输入验证码确认后生效。密钥不发送给第三方二维码服务。确认后立即保存仅显示一次的恢复码，每条只能用一次。后端仅保存恢复码哈希，验证器密钥使用绑定账号身份的 AES-256-GCM 加密。绑定成功撤销该账号旧会话并轮换当前会话。

绑定后密码登录只获得短期 MFA 挑战，通过验证码或恢复码才签发登录会话，不能通过邮件重置密码跳过 MFA。后台所有写操作要求最近 5 分钟完成 MFA；过期时显示验证弹窗，通过后只重试原请求一次，取消不执行操作。关闭 MFA 或重新生成恢复码也需要近期验证。验证码具有时间步重放防护，连续失败会触发限流锁定；请确保服务器及验证器时间准确，同一组验证码用过后需等待下一组。

验证器及全部恢复码同时遗失时，只能联系服务器维护者经线下确认身份后手动重置；不提供邮件绕过或公开恢复接口。MFA 相关表随后端数据库初始化自动创建。配置密钥不会自动为任何管理员开启 MFA，须本人完成绑定。

验证：`npm run test:server` 包括会话、CSRF、TOTP 标准向量、密钥加密、恢复码原子消费、绑定确认与前端二次验证重试测试；真实 MySQL/Redis 的部署连通性及真实账号绑定登录仍需在专用测试环境验收。

## 站点管理与收录

登录后展开头像菜单，选择「站点管理」，进入独立的站点管理页面。页面左侧仅有「站点收录」和「我的站点」两个菜单，右侧展示对应内容。原「提交收录」入口也会跳转至该页面；不提供独立的用户端站点报价页面，旧地址会跳转至「我的站点」。

### 提交站点收录

必填：站点名称、URL（HTTP/HTTPS）、成立时间、网站介绍、支持模型厂商；公开补充说明可选。支持模型厂商与定价页面筛选共用列表、显示名称、Logo 和排序，默认选择 OpenAI、Anthropic、DeepSeek。

收录仅提交公开资料，不接收或保存分组及 KEY，不依赖 SITE_CREDENTIAL_ENCRYPTION_KEY。提交者须确认信息真实有效且有权提交；服务端校验该确认。旧客户端附带的探测字段不会写入新收录记录。历史凭据保持原状，不在本次调整中删除或解密。

左侧预留「模型真伪测试」「延迟与可用性测试」，均为暂未开放的说明页，不接收 KEY、不发起检测、不产生费用。以后再接入独立检测项目，检测不负责获取价格，也不作为站点收录前置条件。

### 收录站点图标

审核通过后，后台异步优先读取 New API 公开 `/api/status` 配置中的自定义 `data.logo`，避免误用框架默认 favicon；没有可用自定义 Logo 时，再获取站点首页声明的高清图标（apple-touch-icon / icon），最后尝试 `/favicon.ico`。自定义 Logo URL 同样经过公网地址、重定向、大小和图片格式校验，不直接透传给浏览器。图标缓存在本站 MySQL 的 `site_logos` 表，通过本站 `/api/site-logos/:id` 提供，不让浏览器直接请求对方站点；数据库备份会包含图标，无需额外文件目录。只有已通过、启用且同意公开的站点图标可访问。抓取或图片加载失败时显示站点名首字，不影响审核和收录。

首次数据库初始化后启动后台扫描，每分钟处理一批（最多 20 个），自动补齐历史已审核站点；抓取成功后每 7 天更新，失败后至少间隔 1 天重试，更新失败保留已有图标。网站地址变更时旧图标不再展示。抓取仅允许公网 HTTP/HTTPS 的标准端口，校验并固定 DNS 地址、逐跳检查重定向，限制响应大小和超时；仅接受 PNG/JPEG/GIF/WebP/ICO，不接收 SVG。支持「我的站点」及管理员「站点管理」通过 Logo URL 手动覆盖（仅限已审核且关联提交的站点），不提供上传。输入后约 600ms 防抖，通过认证后端获取临时预览；预览不写入数据库，浏览器只访问本站，预览响应 no-store。点击保存重新验证并提交正式图片，失败保留原设置和图片；清空 URL 保存恢复自动发现，发现失败也会清除旧自定义图片。重新抓取按钮只刷新已保存设置，失败保留图片并标记可重试。手动地址优先级高于自动发现，定时任务不会以框架 favicon 覆盖；失败约 1 天后重试。设置使用 revision 防止并发保存或后台任务覆盖，外部抓取不占用数据库事务。

接口：用户 `/api/user/sites/:submissionId/logo`，管理员 `/api/admin/providers/:providerId/logo`；GET 读取设置（包含 revision），PATCH `{url, revision}` 保存（空字符串恢复自动）；POST `/preview` `{url}` 返回图片字节，POST `/refetch` `{revision}` 重新抓取，GET `/image` 查看当前缓存（即使未公开也必须验证权限）。公开目录继续使用 `/api/site-logos/:providerId?v=:digest`，只暴露本站缓存地址，使用 ETag 和 no-cache 重验证避免旧自定义图片滞留。URL 最多 2048 字符，仅公网 HTTP/HTTPS 80/443；最大 512 KiB，最多 3 次重定向，单请求 5 秒、总计 15 秒。每进程最多 4 个并行抓取，认证身份预览冷却 500ms，保存/重抓冷却 3 秒，限流状态最多 2000 条、60 秒过期；后台抓取共用并发上限。多进程部署限额按进程生效，不是全局 Redis 限流。运行环境需使用真实公网 DNS；若代理 Fake-IP 模式将站点解析到 `198.18.0.0/15` 等保留地址，抓取会被安全策略拒绝，应为服务进程配置真实公网解析与路由，而非放行保留网段。

管理后台的「站点管理」支持按名称实时筛选、展示状态筛选和数量统计，区分「公开展示」「未公开」「已停用」；启用站点不会覆盖运营者的公开展示意愿。列表展示运营者、模型、计费及发票信息，通过「详情 / 编辑」查看和编辑名称、网址、成立时间、介绍、模型、计费、发票、价格及补充说明；Logo 在详情中单独保存。管理员保存直接生效，后端在同一事务中同步收录资料与目录资料并记录操作日志；网址变更会使旧 Logo 缓存失效并重新抓取。存在待审核修改时，须先处理修改审核再编辑，避免覆盖待审资料。无关联收录记录的历史站点可启停和删除，暂不支持完整资料编辑。启停和删除均需确认，编辑关闭时提示放弃未保存内容，保存期间禁止重复操作。「收录审核」的操作按钮居中显示，已通过的记录仅保留「驳回」操作。

### 我的站点与展示设置

待审核和驳回的申请显示在「提交进度」；管理员审核通过后进入「我的站点」。新申请默认不公开，用户须主动勾选「是否出现在收录列表中」并点击「保存展示设置」。只有审核通过、用户同意公开且管理员启用的站点才会进入服务目录，取消勾选并保存后将从动态目录移除。管理员停用或驳回同样会停止展示，公开接口不包含探测凭据或私密备注。

本地账号和 OAuth 账号的站点按独立身份隔离；历史本地账号提交沿用原有归属。数据库启动初始化会自动添加相关字段，历史站点默认不公开。公开目录、站点详情及 `/welcome` 页面仅使用 `/api/directory` 返回的真实收录数据，不再包含预置演示站点或模拟在线率、延迟、价格和认证数据。加载中显示加载状态，接口失败仅提示重试，不回退到演示数据；无公开站点时展示空状态。未开展探测的在线率与延迟显示「暂无数据」，未提供的发票信息显示「未提供」；列表序号不代表服务质量排名。支持目录搜索、筛选及详情页。

## 收录原则

- 仅整理公开信息，不收录盗号、账号共享、来源不明或明显违反服务商条款的服务。
- 不以付费排名；如未来出现赞助或合作内容，会单独标注。

## 使用提醒

使用第三方中转服务前，请认真阅读其隐私政策、服务条款、退款规则和数据处理说明。API 请求、提示词、文件及密钥可能经过服务商或其上游系统；不要发送个人敏感信息、客户数据、机密代码或未公开资料。为 API 密钥设置最小权限和额度，并定期轮换。

请自行确认服务的使用方式符合所在地法律法规、模型提供方条款及组织内部要求。价格与服务状态可能随时变化，付款前应以服务商当时公布的信息为准。

## 站点分组与公开报价同步

「我的站点」采用紧凑标题与站点计数、带搜索的列表，统一「查看资料 / 分组管理 / 同步分组」操作；查看资料弹窗按站点身份、基本资料、模型覆盖、计费与服务分区，保留底部固定编辑操作；即时公开展示开关移至列表「公开展示」与「操作」之间的「展示设置」列，开启和关闭均须弹窗确认，取消不发送写请求；每站点按北京时间自然日最多成功开启两次，关闭不限次且不扣额度，重复开启不重复扣额度。服务端通过站点行锁在同一事务中校验额度和更新状态，限额返回 429；每日 00:00 重置，列表展示剩余额度。保存失败保留原状态，未审核站点不可设置，不包含分组报价管理入口；窄屏自动改为卡片布局，保留搜索、状态及分页。「用户中心 → 我的站点」的已审核站点提供独立「同步分组」按钮，仅更新数据库分组快照，不要求开启报价展示、不改写价格；成功或失败均至少间隔 5 分钟。点击「分组与报价」进入独立页面（`/site-management/sites/:siteId/pricing`），查看已保存分组、选择站点系统、设置报价公开意愿并手动同步报价；不再嵌入站点详情弹窗。独立页面统一为「分组管理」：顶部仅保留一个「同步分组」按钮，系统类型、报价展示开关集中设置；开启报价展示时一次同步分组与报价，否则仅同步分组。每个分组卡片展示倍率、类型与模型数，相关模型报价收在该分组的折叠明细中；历史报价中的分组仍保留展示，不伪造当前倍率。站点系统或展示设置变更须先保存再同步。分组读写接口为 `GET /api/user/sites/:id/groups` 和 `POST /api/user/sites/:id/groups/sync`，均校验已审核站点所有权，写操作校验来源。此功能不使用 KEY，不发起模型调用，不验证模型真伪，也不测量延迟或实际扣费。报价公开还要求站点审核通过、在服务目录公开且管理员启用。

支持 New API 的公开 /api/pricing 和 Sub2API 的公开 /api/v1/model-plaza。Sub2API 需开放模型广场且有公开分组；若为空、需要登录或停用，不会绕过限制抓取。已核对测试站 sub.omwai.xyz 的接口返回成功但 groups 为空，需站长先开放可展示数据。

公开接口数据只作为参考标价。New API 普通 Token 计费需要模型倍率、输出倍率、可用分组与分组倍率等完整信息；特殊表达式、阶梯、按次等暂不能可靠计算的项会跳过，不使用官方价直接猜测实际收费。模型详情只按精确模型 ID 匹配，不自动合并未知别名；报价对比沿用定价页表格样式，逐行展示序号、站点（Logo 与审核收录标识）、分组、分组倍率及输入 / 输出价格，不展示来源和更新时间列。每站仅保留该模型最低已知倍率分组（同倍率保留首条），全部倍率缺失时保留一条并显示“倍率未知”；先选最低倍率，再搜索，不因搜索切换至其他分组。支持倍率升降序（未知倍率始终排最后）及按同币种、同计价单位比较价格。审核标识仅表示已审核收录，不代表服务质量认证。分组倍率保存公开接口原值，报价已包含该倍率，不应再次相乘。分组探测与报价同步共用安全公开数据读取（DNS 地址校验并固定连接地址、拒绝重定向、超时和响应大小限制），不使用站点 KEY。采集结果事务性保存至 `site_group_snapshots`（完整分组元数据，支持空列表）及 `site_public_groups`（倍率关联）；按站点 ID、当前站点网址和精确分组名关联，区分大小写。详情页及兼容的 `GET /api/probe/groups` 仅查询数据库，不发起上游请求，也不允许访客重新探测。失败时保留最近成功结果，无数据时显示等待服务端更新，不向访客暴露上游错误。

报价快照已记录的倍率始终优先保留。旧公开报价和历史人工报价缺少倍率时，优先关联独立倍率缓存；仍缺失时显示未知，报价对比只读数据库，不会触发上游请求。后台每分钟检查到期站点，每批最多四站、最多四路并发；每站自动采集间隔至少一天，失败也等待一天，跨实例通过数据库行锁认领任务；失败保留原报价，不能精确关联的倍率仍显示“倍率未知”。独立缓存保存获取时间与来源 URL，API 通过 `groupMultiplierDetectedAt`、`groupMultiplierSourceUrl` 和 `groupMultiplierSource` 区分 `price-snapshot` 与 `group-probe`。补齐倍率不更新旧价格、价格同步时间或审核时间，也不反推倍率；表格仍保留六列，独立补齐倍率标注“独立获取 · 非同一快照”，悬停可查看时间和来源。部署后初始化数据库会自动创建倍率缓存及自动获取限流表。

同步失败保留最近成功快照并显示错误；超过 24 小时的数据标记过期。价格仍仅由站长主动同步，同站点两次尝试间隔至少 5 分钟；分组另由服务端每日低频采集，站长主动同步也会更新分组快照。接口必须公开且格式受支持，不能绕过登录或权限限制。

历史人工报价审核接口保留，与自动同步报价分别标记来源。历史分组凭据继续依赖独立的 SITE_CREDENTIAL_ENCRYPTION_KEY（32 字节随机值的 64 位十六进制表示）；新站点收录和公开价格同步不依赖该配置。历史凭据不会被用于此次价格同步。

### MySQL 定价迁移与运行

部署新代码前运行 `npm run db:import-prices`：该命令先执行 `initializeDatabase`，为现有 `model_prices` 添加 `modality`、`billing_unit`、`pricing_details`、`source_name`、`price_checked_at` 列，再从外部 JSON 原样导入全部 12 条既有核对报价（已折算美元，不重复换汇）。重复运行不会覆盖已有人工报价；如需更新现有报价，应审核来源/核对日期后在数据库中更新。运行时 API 不读取 JSON、不访问价格源、不注入任何内置报价；未导入或空库时不会出现这些补充报价。

随后按需运行 `npm run db:sync-prices`（独立 BaseLLM 定价同步）及 `npm run db:sync-rankings`（仅更新 `model_rankings` / `model_ranking_syncs`）。排行榜同步不向定价表写入任何记录，排行榜价格指标仅属于榜单；定价由后台人工新增 / 编辑维护，并保留已有 official / curated 来源及独立同步功能。manual 记录与同步来源身份独立，不被 BaseLLM 替换。历史 `source_id=ranking` 定价及其覆盖已按授权定向清理，未删除排行榜。

`data/legacy-unused-model-prices.json` 仅归档原先未使用的前端静态种子，因无核对日期且当前准确性未知，不自动导入或用于运行时展示。原有服务端核对报价已全部迁移至 `data/curated-model-prices.json`；本次迁移沿用其既有出处与核对日期，不声称重新联网核实。

离线验证：`npx tsc -p tsconfig.server.json --noEmit`；`node --experimental-strip-types --test server\pricing.test.ts server\admin-model-prices.test.ts server\openai-prices.test.ts server\volcengine-media-prices.test.ts`。测试使用内存数据库替身，不连接生产数据库、不发起远程请求。生产部署仍须自行备份并执行上述迁移/导入命令。
